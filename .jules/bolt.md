## 2024-05-19 - [Semantic Cache Listener Concurrency & Allocation Optimization] **Learning:** Identified an event loop starvation bottleneck and unnecessary heap allocation inside the SemanticCache Zenoh subscriber (`aura-core/src/knowledge/cache.rs`). Blocking SQLite queries (`cache.put` and `cache.lookup`) were being executed synchronously inside the async `recv_async()` loop, blocking subsequent event ingestion. Furthermore, `String::from_utf8_lossy` was used, forcing an unnecessary string heap allocation before JSON deserialization. **Action:** Spawning a detached `tokio::spawn` task for each payload ensures concurrent processing, while offloading SQLite operations to `tokio::task::spawn_blocking` keeps Tokio worker threads free. Using `serde_json::from_slice` directly on Zenoh buffer contiguous bytes bypasses the intermediate string allocation.
## 2024-06-25 - [Cedar Policy Parsing Optimization] **Learning:** Identified repetitive O(N) AST parsing overhead in the CapabilityEnforcer. The `PolicySet::from_str` call in `evaluate_cedar_policy` was being evaluated on every authorization request, which adds unnecessary latency. **Action:** Utilizing `std::sync::LazyLock` to cache the pre-compiled `PolicySet` reduces evaluation time and avoids repetitive parsing.
